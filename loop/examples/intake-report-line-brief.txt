WHAT EXISTS TODAY (read before coding; do NOT change any of it):
- bin/ainarres.mjs exports the PURE `formatReport({ board, timeline, trackRecord, governance,
  auditFlags, governanceActions, spendAnomalies, operationalFlags }, { lane })` and
  `reportJson(...)` with the SAME signature. Its LAST section today is the "operational (v6 —
  health & spend watch):" block; before it come the governance / track-record sections. The
  `report` command fetches each view with `restGet(...)` and degrades to [] on error (see the

  audit_flags / governance_actions / spend_anomalies / operational_flags are each fetched
  UNFILTERED and each degrades to [] via `x.httpOk && Array.isArray(x.body) ? x.body : []`).
  Pure-formatter tests live in test/status-format.test.ts.
- `api.open_briefs` — read-only, oversight-scoped, newest-first (created_at desc). One row per
  intake-lane task. Columns: `task_id`, `lane` (always 'intake'), `stage`
  ('proposed_brief' | 'briefed' | 'accepted'), `is_terminal` (bool; true only for accepted),
  `claimed_by_family` (nullable), `age_in_stage`, `subject`, `created_at`, `updated_at`.
  proposed_brief = a brief the intaker is still working; briefed = ready, awaiting a designer;
  accepted = a designer has taken it for decomposition (terminal on the intake lane).

THE FEATURE — ONE TASK (no DB migration; the view is already on main):

1. Extend the PURE `formatReport` first argument with a new field `openBriefs = []` (EXACTLY as
   `spendAnomalies` / `operationalFlags` were added). Render a new INTAKE block IMMEDIATELY
   BEFORE the existing operational block — so section order becomes: … governance → INTAKE →
   operational (operational STAYS last). Keep `formatReport` pure and total (never throw on
   empty/partial input).

   Always print the section header line:
       "intake (v6 — open briefs):"

   Compute three counts from `openBriefs` rows by stage:
       proposed = rows with stage === 'proposed_brief'
       briefed  = rows with stage === 'briefed'
       accepted = rows with stage === 'accepted'
   Then:
   - If `openBriefs` is empty, print exactly one line:
       "  (no briefs)"
   - Otherwise print a summary line:
       "  <proposed> proposed · <briefed> briefed · <accepted> accepted"
     then list the OPEN briefs — rows with stage !== 'accepted', in the given order (the view is
     already newest-first), capped at the 10 most recent — one line each:
       "  - <task_id> — <stage>"
     (If there are open briefs beyond the cap, that is fine — just show the first 10; no extra
     line needed.)

2. Extend the PURE `reportJson` the same way: add `openBriefs = []` to its first argument, and
   include in the returned object a new `intake` field:
       intake: {
         proposed: <count of stage==='proposed_brief'>,
         briefed:  <count of stage==='briefed'>,
         accepted: <count of stage==='accepted'>,
         open:     <openBriefs rows with stage !== 'accepted' (all of them, uncapped)>,
       }
   Leave every existing returned field unchanged.

3. Wire the `report` command (bin/ainarres.mjs) to also fetch `api.open_briefs` (UNFILTERED —
   the view is already scoped to the intake lane; do NOT apply the report's dev-lane filter to

   `openBriefs` to BOTH `formatReport` and `reportJson`. Degrade gracefully to [] if the view is
