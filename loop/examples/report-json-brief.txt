Give `ainarres report` a machine-readable `--json` mode: emit the end-of-run report as a
single structured JSON object (what shipped, who implemented/reviewed/integrated it, the
track record and governance sections), computed by a NEW PURE function `reportJson(...)`.
This mirrors the `status --json` slice already on main: a pure shaping function plus a
one-flag CLI wiring — no consequence, no auth path, no DB migration. It is fully
SUBSTRATE-FREE to validate (a vitest unit test, no database).

NOTE — this brief is SINGLE-USE: the run ships its task to `main`, so a re-run needs a
fresh brief whose work isn't already on main.

WHAT EXISTS TODAY (read before coding; do NOT change the default behavior):
- bin/ainarres.mjs exports the PURE, total `formatReport({ board = [], timeline = [],
  trackRecord = [], governance = [], auditFlags = [], governanceActions = [] } = {},
  { lane = null } = {})` (around line 317) — the HUMAN text renderer. Its unit tests live in
  test/status-format.test.ts (mock board + timeline rows, no substrate).
- Inside formatReport are two PURE derivations you should REUSE (extract them to
  module-scope helpers shared by both functions, or replicate their exact logic):
    - `prFor(taskId)` — the newest-first PR url from a task's transition artifacts
      (`ev.data.artifacts` entry with `type === "pr"` and a `url`), else null.
    - `familyOfTransition(timeline, taskId, from, to)` (already module-scope, line ~285) —
      the acting family string for a task's `from → to` transition, or null.
  formatReport computes, per shipped task: implemented = familyOfTransition(…, "implementing",
  "reviewing"); reviewed = (…, "reviewing", "integrating"); integrated = (…, "integrating",
  "validating"); and "shipped" = board rows with `is_terminal === true`. Cross-family review
  means implemented and reviewed are both non-null AND reviewed !== implemented.
- The `report` command handler (async report, ~line 690) fetches board/timeline plus the
  track-record/governance/audit views and calls `formatReport({...}, { lane })`. The
  per-command `options` map (line ~801+) declares flags; boolean flags read as
  `values.<flag>`. `report` has NO `json` flag yet.

THE FEATURE — ONE TASK (no DB migration; a NEW pure function + one CLI flag):

   `reportJson({ board = [], timeline = [], trackRecord = [], governance = [], auditFlags = [], governanceActions = [] } = {}, { lane = null } = {})`
   to bin/ainarres.mjs. It returns a PLAIN OBJECT (no I/O, no clock, never throws) with
   EXACTLY these keys:
     - `lane`: the lane string, or null.

     - `governance`: the `governance` input, passed through as-is (array).
     - `auditFlags`: the `auditFlags` input, passed through as-is (array).
     - `governanceActions`: the `governanceActions` input, passed through as-is (array).
