# v7.1 plan — the precise service (demand-shaped scaling + push-wake)

> Plan for **v7.1** ([ADR 0026](../decisions/0026-v7-1-demand-shaped-scaling.md) — demand-shaped
> scaling · [ADR 0027](../decisions/0027-v7-1-push-wake.md) — push-wake ·
> design [`precise-service.md`](../design/precise-service.md)). A **refinement of the v7 standing
> service** ([`service.md`](../design/service.md)), not a new capability class: the same
> idle⇄running⇄stalled machine and the same `run_activation` round body, made *precise* — it wakes
> exactly when work arrives and spawns exactly the live roles the work needs. The bigger v8 themes
> (federation, web UI, wider ingress) remain ahead.

## North star

v7 shipped a service that **exists**; it is blunt in two places (both flagged in `service.md`'s own
open risks): it **polls** to wake (up to `LOOP_IDLE_POLL_SECS` of latency) and it **spawns the whole
fleet** on any work (wasted process + token churn; unclaimable stages discovered only by spawning).
v7.1 sharpens both **without touching the demand-scaler-never-router invariant** — every task→worker
binding stays the tiers' own `SKIP LOCKED` self-claim.

## What stays exactly as v7 (do not rebuild)

The state machine; `run_activation`'s structure; `run_pool`/`run_sweep`/`run_concurrent`;
`SKIP LOCKED` self-claim; the single-grok merge queue; the wipe-vs-drain guard; `stop_active`;
`skip_if_banned`; the `stalled` circuit breaker; the local status file; graceful stop; the batch
driver (`make loop-run`) **byte-for-byte** (v7.1 is service-only — the batch driver leaves the new
knobs off, as it already leaves `LOOP_CONSUME_GOVERNANCE` off).

## Milestones

### M27 — demand-shaping (+ the live-capability map)

Scale capacity to the *shape* of demand, matched against *available* capacity.

**Substrate (one blessed touch — read-only view; build ASSISTED):**
- `api.demand` — one row per distinct **required-feature bundle** among pending, claimable-modulo-
  capability tasks (unblocked, dependency-satisfied, no live lease), with a count. Bundle =
  `task.required_features ∪ (an outgoing transition's required_features)` — the *same* predicate
  `claim_next_task` / the `claimable` recovery view apply ([ADR 0009](../decisions/0009-leases-reaper.md)).
  Names no task, no worker, no tier. (`precise-service.md` D1.)

**Service (`driver-lib.sh` / `service.sh` / `roles.sh`; build ASSISTED + mock-verified):**
- `build_capability_map()` at start: probe each configured tier's backend (reachable / model loaded
  / key valid), best-effort + timeboxed + parallel → `CAPMAP = { live tier → role_features }`. A
  per-harness probe, mockable under `LOOP_MODE=mock`. (D2.)
- `refresh_capability_map()`: re-probe down tiers on a slow cadence; mark a tier **down** passively
  when its spawn errors; reclassify a returning backend live with no restart. (D2.)
- `refresh_demand()` once per round (beside `refresh_governance`): read `api.demand` → `DEMAND`;
  unreadable → empty → coarse-gate fallback. (D2.)
- `tier_has_demand(tier)` = `tier ∈ CAPMAP` **and** some `DEMAND` bundle ⊆ `CAPMAP[tier]`. Gate every
  spawn in `run_activation` with it, composing with `skip_if_banned` (spawn iff live ∧ demanded ∧
  not-banned). Pool sizes to `min(implementer-demand-count, LOOP_POOL_SIZE)`. (D2.)
- Unserviceable-demand surface (D3): a demanded bundle no live tier satisfies → status `note` + loud
  log, naming the missing `{features}` **and why** (no configured family vs. providing family
  unreachable); hold, do not spin; do not waste an activation to discover it.

**Selftest phases (mock, deterministic):** review-only board → 0 implementers spawned; single dev
task → 1 implementer (not the pool); bundle no tier provides → surfaced *unconfigured*, no
activation wasted; a tier forced **down** → not spawned, surfaced *backend-down*, then re-probe →
serviceable again, no restart; demand-view / probe outage → v7 fleet-spawn (degrade-safe).

**Gate:** [ADR 0026](../decisions/0026-v7-1-demand-shaped-scaling.md) success criteria 1–4.

### M28 — push-wake

Wake on a database notification the instant claimable work appears — as an optimization *over* the
poll, never instead of it.

**Substrate (one blessed touch — a truth-free trigger; build ASSISTED):**
- An `AFTER INSERT OR UPDATE` trigger on `app.tasks` firing `pg_notify('ainarres_activity', <lane>)`
  on insert or a `stage`/`blocked` change. Persists nothing; a nudge, not truth. ([ADR 0027](../decisions/0027-v7-1-push-wake.md);
  `precise-service.md` D4.) Own the crossing of ADR 0024's ~zero-migration rule explicitly in the
  migration header (truth-free signal, not coordination truth).

**Service (`service.sh`; build ASSISTED + mock-verified):**
- One direct-connection `LISTEN` in the **supervisor only** (`loop.env` creds, `psql`; service-side
  infra, never a harness child — on the correct side of the harness deny-list guard). Feeds arrivals
  to a FIFO under `$RUN_DIR`. (D4.)
- The idle wait becomes "up to `LOOP_IDLE_POLL_SECS` OR until a notification arrives" (`read -t …
  <fifo`). Notification → immediate re-poll; many notifications coalesce to one wake (one activation
  drains all claimable work). LISTEN drop → log, fall back to pure poll, re-establish next tick. (D4/D5.)
- The poll stays as the **backstop** — lengthen its interval since it is no longer primary. It
  covers lazy-reclaim (which emits **no** NOTIFY — [ADR 0009](../decisions/0009-leases-reaper.md)),
  dropped LISTEN, missed notifications, reachability. (D5.)

**Selftest phases (mock, deterministic):** insert into an idle service → wakes in ≪ the poll
interval; LISTEN disabled → still drains via the poll (identical to v7); a lease-expiry-reclaimed
task → still picked up (backstop); the agent surface (zero-dep CLI) and harness guard unchanged.

**Gate:** [ADR 0027](../decisions/0027-v7-1-push-wake.md) success criteria 1–4.

## Build split (recursive, per [ADR 0024](../decisions/0024-v7-scope-the-standing-service.md) §bootstrap)

- **Assisted (mock-verified before live):** `api.demand` (DB view — never swarm-self-validated in a
  worktree, the wipe lesson); the capability map + probe + demand gate + pool sizing in
  `driver-lib.sh` (trust-critical spawn logic — routing-drift / wrongly-withheld-tier is the failure
  class); the `pg_notify` trigger migration (substrate behavior); the LISTEN-or-poll idle wait in
  `service.sh` (the wake path).
- **Swarm-built (briefed, run hands-off):** the pure, substrate-free **precision report-line +
  formatter** — takes `demand=[]` + tier capabilities and renders the human-facing lines (open
  demand by capability, the unserviceable/backend-down callouts); `npx vitest`, no DB (the M20–M24
  pure-formatter pattern). The recursion, again: **let the standing service deliver its own
  precision-report slice hands-off** — now *faster* (push-wake) and *cheaper* (demand-shaping) than
  the v7 service that built its status readout.

## Ordering & dependencies

M27 before M28: demand-shaping is the substantive change and the invariant-adjacent one; push-wake
is a latency optimization that layers cleanly on top (a woken service *then* consults the capability
map + demand to spawn). Neither blocks the other structurally, but M27 first keeps the riskier
(invariant-touching) change ahead of the cosmetic-latency one. Each milestone is its own PR, ends
green (`service-selftest` + `loop-selftest` no-regression + full suite), one blog on merge.

## Out of scope (explicitly)

- **Cost-aware routing** — using track record / task content to prefer one capable family over
  another. That crosses the router line ([ADR 0026](../decisions/0026-v7-1-demand-shaped-scaling.md)
  bright line); v7.1 does demand-*shaping* only.
- **Push-wake as the sole wake path** — the poll backstop is permanent (lazy reclaim emits no
  NOTIFY).
- **Federation / multi-service / web UI / wider ingress** — v8, built on the `api.demand` split and
  the precise service, not here.
- **A heartbeat *table*** — liveness stays a local file ([`service.md`](../design/service.md) D4);
  multi-service liveness is v8.
